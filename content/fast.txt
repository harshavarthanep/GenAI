## F01 | compass | GenAI & LLM Core Concepts | The 20 ideas every GenAI interview starts with
META: time = 4 hours
WHY: Interviewers open with fundamentals. If you can explain tokens, transformers, context windows and hallucinations clearly, you pass the first filter at almost every company.
LEARN: AI vs ML vs DL vs GenAI; How LLMs generate text; Tokens and context windows; Transformers and attention; Pretraining, fine-tuning, RLHF; Sampling settings; Hallucinations

### The AI family in one minute | B
POINT: **AI** = machines doing tasks that need human-like intelligence.
POINT: **ML** = learning patterns from data instead of hand-written rules.
POINT: **Deep learning** = ML with many-layered neural networks.
POINT: **Generative AI** = deep learning that creates new text, images, audio or code.
POINT: **LLM** = a large Transformer trained to predict the next token on massive text data.
E: A spam filter is ML (it labels). Drafting the reply email is GenAI (it creates).
---

### How an LLM answers | B
FLOW: Prompt > Tokenise > Embed + position > Attention layers > Next-token probabilities > Sample > Repeat until stop
POINT: The model produces **one token at a time**; each new token is appended and fed back in (autoregressive generation).
POINT: **Tokens** are sub-word chunks; about 4 characters or ¾ of an English word.
POINT: The **context window** is the maximum tokens (input + output) per request; the model has no memory beyond it.
---

### Transformer and attention | I
POINT: **Self-attention** lets every token weigh every other token using Query, Key and Value vectors: `softmax(QKᵀ/√d)·V`.
POINT: **Multi-head** attention runs several attention patterns in parallel (syntax, coreference, topic).
POINT: **Positional encoding** gives word order, because attention itself is order-blind.
POINT: Families: **encoder-only** (BERT: understand), **decoder-only** (GPT, Claude, Llama, Gemini: generate), **encoder-decoder** (T5: translate/summarise).
POINT: Why transformers beat RNNs: parallel training on GPUs and long-range dependencies without vanishing gradients.
---

### Training stages | I
FLOW: Pretraining (next-token on trillions of tokens) > Supervised fine-tuning (instruction → answer) > Preference tuning (RLHF / DPO) > Deployment + safety layers
POINT: **Base model** completes text; **instruct/chat model** follows instructions.
POINT: **RLHF**: humans rank outputs → reward model → policy optimised. **DPO** learns directly from chosen/rejected pairs.
---

### Sampling settings | B
TABLE: Generation controls
| Setting | Effect | Typical value |
| Temperature | Randomness of token choice | 0–0.3 factual, 0.7–1 creative |
| Top-p | Sample from smallest set with cumulative probability p | 0.9 |
| Top-k | Sample from k most likely tokens | 40 |
| Max tokens | Caps output length and cost | Task-dependent |
| Stop sequences | End generation at a marker | `</answer>` |
---

### Hallucinations | B
POINT: Confident but false output, because the model optimises for **plausible** text, not verified truth.
POINT: Fixes: **RAG grounding**, citations, low temperature, tool use for facts/maths, allow "I don't know", human review for high-stakes use.
---

IQ: What is a Large Language Model? => A large Transformer-based neural network, typically decoder-only, pretrained on trillions of tokens with a next-token prediction objective, then instruction-tuned and preference-aligned so it can follow instructions, reason and generate text. => A super-powered autocomplete that has read most of the internet and learned to be a helpful assistant.
IQ: Explain self-attention. => Each token is projected into query, key and value vectors. Attention scores are the scaled dot products of a token's query with all keys, normalised by softmax, and used to take a weighted sum of values. This lets each token gather context from every other token in parallel. => Every word looks at all the other words and decides which ones matter for understanding it.
IQ: What limits the context window and why does it matter? => Attention cost grows roughly quadratically with sequence length, plus memory for the KV cache. The window bounds how much prompt, history and retrieved context fits; exceeding it forces truncation, summarisation or retrieval. => It is the model's whiteboard. Anything not on it, the model cannot see.
IQ: Base model vs instruct model? => A base model is only pretrained and continues text. An instruct model is further trained with SFT and preference optimisation to follow instructions, refuse unsafe requests and format answers helpfully. => The base model is well-read; the instruct model has also been trained to be a good assistant.
IQ: How would you reduce hallucinations in production? => Ground with retrieval and require citations, constrain with system instructions and structured outputs, lower temperature, route facts and maths to tools, add an abstain path, evaluate faithfulness on a golden set, and keep human review for high-risk outputs. => Give it the right documents, tell it to say "I don't know", and check its work.
PRACTICE: Explain LLMs to a non-technical friend in 2 minutes; Count tokens of one paragraph in English and Tamil using any free tokenizer viewer; Ask the same question at temperature 0 and 1 in Google AI Studio and compare

import json

def parse_llm_json(text: str, default=None):
    """Safely parse JSON returned by an LLM, stripping code fences."""
    cleaned = text.strip().removeprefix("```json").removesuffix("```").strip()
    try:
        return json.loads(cleaned)
    except json.JSONDecodeError:
        return default

### Generators, decorators, async | I
POINT: **Generator** (`yield`): produce items lazily; used for streaming LLM tokens and reading big files.
POINT: **Decorator**: wraps a function to add retry, timing, caching or logging.
POINT: **async/await** + `asyncio.gather`: run many API calls concurrently.
```python
import functools, time
def retry(times=3):
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*a, **k):
            for i in range(times):
                try: return fn(*a, **k)
                except Exception as e:
                    print("retry", i + 1, e); time.sleep(0.1 * 2 ** i)
            raise RuntimeError("failed")
        return wrapper
    return deco
```

### Coding interview patterns | I
TABLE: Patterns that solve most easy/medium problems
| Pattern | Typical question |
| Hash map counting | Two-sum, anagrams, first unique character |
| Two pointers | Palindrome check, pair with target in sorted array |
| Sliding window | Longest substring without repeats, max sum of k elements |
| Stack | Valid parentheses, next greater element |
| Sorting + scan | Merge intervals, meeting rooms |
| BFS / DFS | Islands in grid, tree depth |
| Binary search | Search in sorted array, first bad version |
```python
def two_sum(nums, target):
    seen = {}
    for i, n in enumerate(nums):
        if target - n in seen:
            return [seen[target - n], i]
        seen[n] = i
print(two_sum([2, 7, 11, 15], 9))   # [0, 1]

def longest_unique(s):
    start, best, last = 0, 0, {}
    for i, ch in enumerate(s):
        if ch in last and last[ch] >= start:
            start = last[ch] + 1
        last[ch] = i
        best = max(best, i - start + 1)
    return best
print(longest_unique("abcabcbb"))    # 3
```
TIP: In interviews, say the brute force first, then optimise, then state time and space complexity (Big-O).

IQ: List vs tuple vs set vs dict? => Lists are ordered and mutable; tuples are ordered and immutable (hashable if their items are); sets are unordered collections of unique hashable items with O(1) average membership; dicts map hashable keys to values with O(1) average lookup and preserve insertion order. => List = shopping list, tuple = fixed GPS point, set = unique guest list, dict = phonebook.
IQ: What is a generator and why use it? => A function using yield that returns a lazy iterator, producing values on demand and keeping state between calls. It saves memory for large or infinite sequences and is natural for streaming. => It gives you one item at a time instead of loading everything at once, like streaming a movie.
IQ: Explain the GIL. => CPython's Global Interpreter Lock allows only one thread to execute Python bytecode at a time. Threads still help for I/O-bound work like API calls; CPU-bound work uses multiprocessing or native libraries such as NumPy. Newer Python versions offer an optional free-threaded build. => Python threads take turns, so use them for waiting tasks, not heavy maths.
IQ: Shallow vs deep copy? => A shallow copy creates a new outer object but shares nested objects; a deep copy (copy.deepcopy) recursively copies everything. => Shallow copy photocopies the folder; deep copy photocopies every page inside too.
IQ: What does a decorator do? => It is a higher-order function that takes a function and returns a wrapped version, adding behaviour such as retries, caching, auth or logging without modifying the original code. => Gift-wrapping a function with extra features.

## F03 | database | SQL for Interviews | The queries that appear in almost every data and AI interview
META: time = 6 hours
WHY: SQL rounds are common for AI engineer, data scientist and analyst roles. Most questions reuse the same 8 patterns.
LEARN: SELECT to HAVING; All JOINs; CTEs and subqueries; Window functions; Classic interview problems; Execution order

### Core syntax and execution order | B
FLOW: FROM / JOIN > WHERE > GROUP BY > HAVING > SELECT > DISTINCT > ORDER BY > LIMIT
```sql
SELECT c.city, COUNT(*) AS orders, SUM(o.amount) AS revenue
FROM orders o
JOIN customers c ON c.id = o.customer_id
WHERE o.amount > 100
GROUP BY c.city
HAVING SUM(o.amount) > 500
ORDER BY revenue DESC
LIMIT 5;
```
---

### JOINs at a glance | B
TABLE: JOIN types
| JOIN | Returns |
| INNER | Rows matching in both tables |
| LEFT | All left rows + matches (NULL if none) |
| RIGHT | All right rows + matches |
| FULL OUTER | Everything from both sides |
| CROSS | Every combination (m × n rows) |
| SELF | Table joined to itself (employee → manager) |
---

### Window functions | I
```sql
SELECT customer_id, order_id, amount,
  ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY amount DESC) AS rn,
  SUM(amount)  OVER (PARTITION BY customer_id ORDER BY order_id)    AS running_total,
  amount - LAG(amount) OVER (ORDER BY order_id)                     AS change_vs_prev
FROM orders;
```
POINT: `ROW_NUMBER` unique; `RANK` ties then gap; `DENSE_RANK` ties without gaps.
---

### The 8 classic interview problems | I
TABLE: Patterns
| Problem | Approach |
| Nth highest salary | `DENSE_RANK()` in CTE, filter rank = N |
| Top N per group | `ROW_NUMBER() OVER (PARTITION BY g ORDER BY x DESC)` ≤ N |
| Duplicates | `GROUP BY cols HAVING COUNT(*) > 1` |
| Delete duplicates keep one | `ROW_NUMBER()` > 1 → delete |
| Customers with no orders | `LEFT JOIN ... WHERE o.id IS NULL` |
| Running total | `SUM() OVER (ORDER BY date)` |
| Month-on-month growth | `LAG()` over monthly aggregate |
| Consecutive days / streaks | `date - ROW_NUMBER()` grouping trick |
```sql
-- Second highest order amount
WITH r AS (SELECT amount, DENSE_RANK() OVER (ORDER BY amount DESC) AS rk FROM orders)
SELECT DISTINCT amount FROM r WHERE rk = 2;

-- Customers who never ordered
SELECT c.name FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.order_id IS NULL;
```
---

IQ: WHERE vs HAVING? => WHERE filters individual rows before grouping and cannot use aggregates; HAVING filters groups after GROUP BY and can use aggregates like SUM or COUNT. => WHERE picks rows, HAVING picks groups.
IQ: RANK vs DENSE_RANK vs ROW_NUMBER? => ROW_NUMBER assigns unique sequential numbers; RANK gives ties the same rank and skips the next ranks; DENSE_RANK gives ties the same rank without gaps. => For scores 100, 100, 90: row number 1,2,3; rank 1,1,3; dense rank 1,1,2.
IQ: What is an index and when can it hurt? => A data structure, usually a B-tree, that speeds up lookups on columns used in WHERE, JOIN and ORDER BY. It costs storage and slows INSERT/UPDATE/DELETE because the index must be maintained. => A book's index: faster finding, but every new page means updating the index.
IQ: Explain ACID. => Atomicity (all or nothing), Consistency (constraints always hold), Isolation (concurrent transactions don't interfere), Durability (committed data survives failures). => Bank transfers either fully happen or not at all, and never get lost.
IQ: How would you let an LLM query a database safely? => Provide schema context, generate SQL with structured output, validate and lint it, run with a read-only least-privilege user, add row limits and timeouts, block DDL/DML, log queries, and show the SQL to the user. => Let the AI write the query, but only allow it to read, and check it before running.
PRACTICE: Solve all 8 SQL lab challenges; Write the second-highest and top-2-per-group queries from memory; Explain your query's execution order out loud

### ML core ideas | B

IQ: Precision vs recall, with an example? => Precision is the fraction of predicted positives that are correct; recall is the fraction of actual positives found. A fraud model with high precision rarely flags honest users; high recall catches most fraud. They trade off via the decision threshold. => Precision: when it says yes, is it right? Recall: did it find all the yeses?
IQ: How do you detect and fix overfitting? => Compare training and validation performance or learning curves; a large gap signals overfitting. Fix with more or augmented data, regularisation (L1/L2, dropout), simpler models, early stopping, cross-validation and removing leaky features. => The model memorised the practice paper; give it more variety and make it simpler.
IQ: Bagging vs boosting? => Bagging trains models independently on bootstrap samples and averages them to reduce variance (random forest). Boosting trains models sequentially, each correcting the previous errors, reducing bias (XGBoost, LightGBM). => Bagging asks many friends at once; boosting is one student improving after every mistake.
IQ: What is data leakage? => When training features contain information unavailable at prediction time or derived from the target, inflating validation scores and failing in production. Prevent with time-based splits, fitting preprocessing only on training folds and careful feature review. => The model secretly saw the answers during practice.

## F05 | brain | Deep Learning & NLP Essentials | Neural networks, embeddings and tokenisation in one sprint
META: time = 5 hours

### Neural network essentials | B
POINT: Neuron = weighted sum + bias → activation (ReLU, GELU, sigmoid, softmax).
POINT: **Loss** measures error (MSE for numbers, cross-entropy for classes and next tokens).
POINT: **Backpropagation** computes gradients with the chain rule; the **optimiser** (SGD, Adam/AdamW) updates weights.
POINT: **Epoch** = full pass; **batch** = subset per update; **learning rate** = step size.
POINT: Regularise with dropout, weight decay, early stopping, data augmentation.
```python
import numpy as np
x, y = np.array([1.0, 2.0, 3.0]), np.array([2.0, 4.0, 6.0])
w, lr = 0.0, 0.05
for epoch in range(100):
    pred = w * x
    grad = 2 * np.mean((pred - y) * x)   # d(MSE)/dw
    w -= lr * grad
print(round(w, 3))                       # ≈ 2.0
```
---

### Architectures compared | I
TABLE: Architectures
| Architecture | Best for | Key idea |
| CNN | Images | Filters detect local patterns |
| RNN / LSTM | Short sequences (legacy) | Step-by-step memory |
| Transformer | Text, code, images, audio | Attention over all tokens in parallel |

### Text to numbers | B
FLOW: Raw text > Tokeniser (BPE / WordPiece / SentencePiece) > Token IDs > Embedding vectors > Model
POINT: **Subword tokenisation** handles rare words and typos with a fixed vocabulary.
POINT: **Embeddings** place similar meanings close together; compare with **cosine similarity**.
POINT: Classic NLP: TF-IDF, stemming, lemmatisation, NER, sentiment; still useful for cheap baselines and hybrid search.
---

IQ: Why use ReLU instead of sigmoid in hidden layers? => ReLU is cheap and does not saturate for positive inputs, reducing vanishing gradients and speeding training; sigmoid saturates at both ends. Variants such as GELU and SwiGLU are used in transformers. => Sigmoid gets "stuck" for big numbers; ReLU keeps learning.
IQ: What is the vanishing gradient problem? => In deep or recurrent networks, gradients shrink exponentially as they propagate backwards, so early layers barely learn. Mitigations include ReLU-family activations, residual connections, normalisation and attention-based architectures. => The feedback gets weaker and weaker until the first layers hear nothing.
IQ: What are embeddings? => Dense vector representations learned so that semantic similarity maps to geometric closeness; used for search, clustering, recommendations and as model inputs. => Coordinates on a meaning-map.
IQ: Adam vs SGD? => SGD updates with a fixed learning rate (often with momentum); Adam keeps per-parameter adaptive learning rates using running averages of gradients and squared gradients, converging faster with less tuning. AdamW adds decoupled weight decay and is standard for transformers. => Adam automatically adjusts step size for every weight.

## F08 | library | Embeddings, Vector DBs & RAG | The number one GenAI pattern in companies
META: time = 8 hours
WHY: RAG questions appear in nearly every GenAI interview and system design round. Know the pipeline, the trade-offs and how to evaluate it.

### The pipeline | B
FLOW: Load > Clean > Chunk > Embed > Index (vector DB) > Retrieve top-k > Rerank > Augment prompt > Generate with citations
POINT: Chunk 300–800 tokens with 10–20% overlap; keep metadata (source, page, section, date, access level).
POINT: **Hybrid search** = BM25 keywords + vectors, merged (e.g. reciprocal rank fusion).
POINT: **Reranker** (cross-encoder) re-scores top 20–50 candidates; keep top 3–8.
---

### Vector search essentials | I
TABLE: Vector concepts
| Concept | Meaning |
| Cosine similarity | Angle-based similarity of embeddings |
| ANN index (HNSW, IVF) | Approximate nearest neighbours in milliseconds |
| Metadata filtering | Restrict by tenant, date, department, permissions |
| Vector DBs | Chroma, FAISS, Qdrant, Weaviate, Milvus, pgvector, Pinecone |
---

### Evaluating RAG | I
TABLE: Metrics
| Layer | Metric |
| Retrieval | Recall@k, hit rate, MRR, nDCG |
| Generation | Faithfulness / groundedness, answer relevance, citation accuracy |
| System | Latency p95, cost per query, user feedback |
POINT: Build a **golden set** of real questions with expected answers and source passages; rerun on every change.
---

### Advanced RAG menu | A
TABLE: Techniques
| Technique | Solves |
| Query rewriting / multi-query | Vague or differently-worded questions |
| HyDE | Short queries with weak signal |
| Parent-child / small-to-big | Precise match + enough context |
| Contextual chunk headers | Chunks that lose meaning alone |
| GraphRAG | Relationship and multi-hop questions |
| Agentic RAG | Iterative, multi-source research |
---

IQ: Walk me through a RAG pipeline. => Ingest and parse documents, clean them, chunk with overlap while preserving structure and metadata, embed chunks, and index them in a vector store, often alongside BM25. At query time, optionally rewrite the query, run hybrid retrieval, rerank, assemble a grounded prompt with citations and generate. Evaluate retrieval and generation separately and monitor in production. => Find the right pages first, then let the AI answer using only those pages.
IQ: How do you choose chunk size? => Balance precision and context: smaller chunks retrieve precisely but lose context; larger chunks keep context but dilute similarity and cost more tokens. Start around 300–800 tokens with overlap, follow document structure, and tune empirically using retrieval recall on a golden set. => Like pizza slices: not too big, not too small, and test what works.
IQ: RAG vs fine-tuning? => RAG injects external, updatable knowledge at query time with citations and access control; fine-tuning changes model behaviour, style or task skill. Use RAG for knowledge, fine-tuning for format or behaviour, and combine when needed. => RAG gives the model a book; fine-tuning changes how the model writes.
IQ: Retrieval looks right but answers are wrong. What do you check? => Context ordering and length (lost-in-the-middle), conflicting chunks, prompt instructions for grounding, temperature, citation requirements, truncation, and whether the model is the bottleneck; measure faithfulness with an evaluator and inspect traces. => Check what the AI actually received and how it was told to use it.
PRACTICE: Build the in-browser RAG demo in the RAG Lab with your own text; Compare chunk sizes 200 vs 600 on 5 questions; Write a 20-question golden set for one document

### Agent fundamentals | B

### MCP in one table | I
TABLE: Model Context Protocol
| Piece | Role |
| Host / client | AI app (desktop assistant, IDE, agent) |

IQ: What is an AI agent and how is it different from a chatbot? => An agent uses an LLM to plan and take actions through tools in a loop, observing results until a goal is met, often with memory and stopping criteria. A chatbot only produces conversational responses. => A chatbot tells you how to book a ticket; an agent books it.
IQ: When would you not use an agent? => When the task is predictable and can be a deterministic workflow, when latency or cost budgets are tight, when actions are high-risk without human review, or when evaluation is hard. Simpler pipelines are cheaper and more reliable. => If a checklist works, don't hire a decision-maker.
IQ: What is MCP? => The Model Context Protocol is an open standard for connecting AI applications to external tools and data. Servers expose tools, resources and prompts; clients in hosts discover and call them over standard transports, avoiding one-off integrations. => USB-C for AI: one plug that works with many apps.
IQ: How do you evaluate an agent? => Task success rate on scenario suites, step and tool-call efficiency, cost and latency, safety violations, recovery from tool errors, and human-intervention rate, using traces and sandboxed environments. => Did it finish the job, how much did it cost, and did it do anything dangerous?

IQ: When would you fine-tune instead of using RAG? => When you need consistent style, format or a specialised skill, lower latency or cost via a smaller model, or behaviour that prompting cannot achieve reliably. Not for frequently changing facts, which belong in RAG. => Fine-tune to change how it behaves; RAG to change what it knows.
IQ: Explain LoRA. => LoRA freezes pretrained weights and learns low-rank update matrices for selected layers, so only a small fraction of parameters train. Adapters are small, swappable and cheap to train; QLoRA combines this with 4-bit quantisation of the base model. => Sticky notes on a textbook instead of reprinting it.
IQ: How do you evaluate an LLM application before launch? => Define success criteria, build a representative golden set with edge and adversarial cases, combine deterministic checks with rubric-based LLM-as-judge and human review, compare versions, and gate deployment on thresholds; then monitor online with feedback and drift metrics. => Test it on a fixed exam every time you change it, and keep watching after launch.
IQ: What do you monitor in production? => Latency (p50/p95), error and rate-limit rates, tokens and cost per request, retrieval quality, user feedback, safety flags, and drift in input topics, with traces for debugging. => Speed, cost, errors, happiness and safety.
