## sql | database | SQL | Queries, joins, windows, performance and the classic interview problems
### Query skeleton and order
```sql
SELECT col, AGG(x) AS a        -- 5
FROM t JOIN u ON ...           -- 1
WHERE row_filter               -- 2
GROUP BY col                   -- 3
HAVING group_filter            -- 4
ORDER BY a DESC                -- 6
LIMIT 10;                      -- 7
```
### Filtering
ROW: Comparison :: `=`, `<>`, `>`, `BETWEEN a AND b`, `IN (...)`, `LIKE 'A%'`, `ILIKE` (Postgres)
ROW: NULL :: `IS NULL`, `IS NOT NULL`, `COALESCE(x, 0)`, `NULLIF(a, b)`
ROW: Conditional :: `CASE WHEN x > 0 THEN 'pos' ELSE 'neg' END`
ROW: Dedupe :: `SELECT DISTINCT`, `COUNT(DISTINCT col)`
### Joins
ROW: INNER :: Matches only
ROW: LEFT :: All left rows; anti-join with `WHERE right.id IS NULL`
ROW: FULL OUTER :: All rows both sides
ROW: CROSS :: Cartesian product
ROW: SELF :: `employees e JOIN employees m ON e.manager_id = m.id`
ROW: Semi-join :: `WHERE EXISTS (SELECT 1 FROM ...)`
### Window functions
```sql
ROW_NUMBER() OVER (PARTITION BY g ORDER BY x DESC)
RANK() / DENSE_RANK() OVER (ORDER BY score DESC)
SUM(x) OVER (ORDER BY d ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
AVG(x) OVER (ORDER BY d ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)   -- 7-day moving average
LAG(x, 1) OVER (ORDER BY d), LEAD(x) OVER (...), NTILE(4) OVER (...)
FIRST_VALUE(x) OVER (PARTITION BY g ORDER BY d)
```
### Classic problems
```sql
-- Nth highest
WITH r AS (SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) rk FROM emp)
SELECT DISTINCT salary FROM r WHERE rk = 3;
-- Top 2 per department
SELECT * FROM (SELECT *, ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) rn FROM emp) t
WHERE rn <= 2;
-- Duplicates
SELECT email, COUNT(*) FROM users GROUP BY email HAVING COUNT(*) > 1;
-- Month-on-month growth
WITH m AS (SELECT DATE_TRUNC('month', d) mon, SUM(amt) rev FROM sales GROUP BY 1)
SELECT mon, rev, ROUND(100.0 * (rev - LAG(rev) OVER (ORDER BY mon)) / LAG(rev) OVER (ORDER BY mon), 1) pct FROM m;
-- Streaks (consecutive login days)
SELECT user_id, MIN(d), MAX(d), COUNT(*) days FROM
 (SELECT user_id, d, d - (ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY d)) * INTERVAL '1 day' grp FROM logins) t
GROUP BY user_id, grp HAVING COUNT(*) >= 3;
```
### Design and performance
ROW: Keys :: Primary key (unique, not null), foreign key (referential integrity), unique, check, default
ROW: Normal forms :: 1NF atomic values; 2NF no partial dependency; 3NF no transitive dependency
ROW: Indexes :: B-tree for equality/range; composite index follows leftmost-prefix rule
ROW: EXPLAIN :: `EXPLAIN ANALYZE` shows the plan: look for sequential scans on big tables
ROW: ACID :: Atomicity, Consistency, Isolation, Durability
ROW: Isolation levels :: Read uncommitted < read committed < repeatable read < serializable
ROW: OLTP vs OLAP :: Many small transactions vs large analytical scans (warehouses, columnar)
ROW: Star schema :: Fact table (events, measures) + dimension tables (who, what, when, where)
ROW: pgvector :: `ORDER BY embedding <=> query_vec LIMIT k` (cosine distance)
WARN: Traps: `= NULL` never matches; `COUNT(col)` skips NULLs but `COUNT(*)` doesn't; integer division in some engines; aliases are not usable in WHERE; LEFT JOIN turns into INNER when you filter the right table in WHERE.

## stats | sigma | Maths & Statistics | Linear algebra, probability, statistics and calculus for AI
### Linear algebra
ROW: Vector / matrix / tensor :: 1-D list / 2-D grid / n-D array of numbers
ROW: Dot product :: `a·b = Σ aᵢbᵢ`; large when vectors align
ROW: Cosine similarity :: `a·b / (‖a‖‖b‖)` in [−1, 1]
ROW: Matrix multiply :: (m×n)(n×p) → (m×p); each layer of a network is `XW + b`
ROW: Eigenvectors / PCA :: Directions of maximum variance
ROW: Norms :: L1 = Σ|x| (sparsity), L2 = √Σx² (regularisation)
### Probability
ROW: Conditional :: `P(A|B) = P(A∩B) / P(B)`
ROW: Bayes :: `P(A|B) = P(B|A) P(A) / P(B)`
ROW: Independence :: `P(A∩B) = P(A) P(B)`
ROW: Expected value :: `E[X] = Σ x P(x)`
ROW: Distributions :: Bernoulli, binomial, Poisson (counts), normal, uniform, exponential
ROW: Softmax :: `exp(zᵢ) / Σ exp(zⱼ)`; temperature divides z before softmax
### Statistics
ROW: Central tendency :: Mean (sensitive to outliers), median (robust), mode
ROW: Spread :: Variance, standard deviation, IQR
ROW: CLT :: Sample means are approximately normal for large n
ROW: Hypothesis test :: H₀ vs H₁; p-value < α (e.g. 0.05) → reject H₀
ROW: Errors :: Type I = false positive (α); Type II = false negative (β); power = 1 − β
ROW: Confidence interval :: Range likely to contain the true parameter at a given confidence
ROW: Tests :: t-test (means), chi-square (categories), ANOVA (3+ groups)
ROW: Correlation :: Pearson (linear), Spearman (rank); correlation ≠ causation
### Calculus and optimisation
ROW: Derivative :: Rate of change / slope
ROW: Chain rule :: `d/dx f(g(x)) = f'(g(x)) g'(x)`, the core of backprop
ROW: Gradient descent :: `θ ← θ − η ∇L(θ)`
ROW: Convex :: One global minimum; neural nets are non-convex
### Information theory
ROW: Entropy :: Uncertainty: `−Σ p log p`
ROW: Cross-entropy :: Loss for classification / next-token prediction
ROW: KL divergence :: How one distribution differs from another (used in RLHF, distillation)
ROW: Perplexity :: `exp(cross-entropy)`; lower = better language model

## llm | layers | Transformers & LLMs | Architecture, training, inference and model selection
### Architecture
ROW: Attention :: `softmax(QKᵀ/√dₖ) V`
ROW: Multi-head :: Several attention heads concatenated
ROW: Causal mask :: Decoder tokens see only previous tokens
ROW: Positional info :: Sinusoidal, learned, RoPE (rotary), ALiBi
ROW: Block :: Attention → add & norm → feed-forward → add & norm
ROW: Families :: Encoder (BERT), decoder (GPT, Claude, Llama, Gemini), encoder-decoder (T5)
ROW: MoE :: Mixture-of-Experts routes each token to a few expert networks; more capacity per FLOP

ROW: Pretraining :: Next-token prediction on trillions of tokens
ROW: SFT :: Supervised instruction tuning
ROW: Preference tuning :: RLHF (reward model + PPO), DPO, RLAIF / constitutional methods
ROW: Reasoning training :: RL on verifiable tasks (maths, code) to improve step-by-step thinking
ROW: Scaling laws :: Loss falls predictably with parameters, data and compute

ROW: Decoding :: Greedy, beam search, sampling (temperature, top-p, top-k)
ROW: KV cache :: Stores past keys/values to avoid recomputation
ROW: Quantisation :: 8-bit / 4-bit weights (GPTQ, AWQ, GGUF)
ROW: Speculative decoding :: Small draft model proposes tokens; big model verifies
ROW: Batching :: Continuous batching (e.g. vLLM) for throughput
ROW: Context length :: Long context vs retrieval trade-off; "lost in the middle" effect
### Choosing a model
ROW: Quality :: Task benchmarks + your own evaluation set
ROW: Cost / latency :: Price per million tokens, time-to-first-token, tokens per second
ROW: Privacy :: API vs self-hosted open weights
ROW: Features :: Tool calling, structured output, vision, long context, fine-tuning support
ROW: Licence :: Check open-weight licences for commercial use

## rag | library | Vectors & RAG | Embeddings, vector databases, retrieval and evaluation
### Pipeline
FLOW: Ingest > Parse > Chunk > Embed > Index > Retrieve > Rerank > Generate > Evaluate
### Design choices
ROW: Chunking :: Fixed, recursive, structure-aware, semantic; 300–800 tokens, 10–20% overlap
ROW: Embedding model :: Quality on your language/domain, dimensions, cost, speed
ROW: Index :: HNSW (fast, memory-heavy), IVF (clustered), flat (exact, small data)
ROW: Distance :: Cosine, dot product, Euclidean (normalise vectors for cosine)
ROW: Hybrid :: BM25 + dense; fuse with reciprocal rank fusion
ROW: Reranker :: Cross-encoder over top-N candidates
ROW: Metadata :: Source, page, section, date, tenant, ACL; filter before ranking
ROW: Context assembly :: Deduplicate, order by relevance, cite sources, respect token budget
### Advanced
ROW: Query rewriting :: Clarify / expand the question
ROW: Multi-query / RAG-Fusion :: Several queries, merged results
ROW: HyDE :: Embed a hypothetical answer
ROW: Parent-child :: Retrieve small, return larger parent
ROW: Contextual retrieval :: Prepend chunk-specific context before embedding
ROW: GraphRAG :: Entity graph + community summaries
ROW: Agentic RAG :: Agent decides searches iteratively
### Evaluation
ROW: Retrieval :: Recall@k, precision@k, MRR, nDCG, hit rate
ROW: Generation :: Faithfulness, answer relevance, context precision/recall, citation accuracy
ROW: Tools :: RAGAS, DeepEval, TruLens, Arize Phoenix (open source)
WARN: Common failures: bad PDF parsing, chunks without context, stale indexes, missing permissions filtering, too many chunks (noise), no abstain path.

## finetune | sliders | Fine-tuning | SFT, PEFT, LoRA, alignment and evaluation
### When
ROW: Fine-tune for :: Style, format, narrow skill, smaller/faster model, consistent behaviour
ROW: Don't fine-tune for :: Fresh or frequently changing facts (use RAG)
### Methods
ROW: SFT :: Train on prompt → ideal response pairs
ROW: Full fine-tuning :: Update all weights; expensive
ROW: PEFT :: Update few parameters (LoRA, prefix tuning, adapters)
ROW: LoRA :: Low-rank matrices A·B added to weight updates; rank r, alpha, target modules
ROW: QLoRA :: LoRA on 4-bit (NF4) quantised base model
ROW: Distillation :: Student mimics teacher outputs
ROW: Preference :: RLHF (PPO with reward model), DPO, ORPO, KTO
### Data
ROW: Format :: JSONL chat messages; consistent system prompts
ROW: Size :: Hundreds to thousands of high-quality varied examples
ROW: Split :: Hold out a test set; deduplicate; remove PII
### Hyperparameters
ROW: Learning rate :: ~1e-4 to 2e-4 for LoRA (lower for full fine-tunes)
ROW: Epochs :: 1–3; watch validation loss
ROW: Rank r :: 8–64; higher = more capacity
### Risks
ROW: Overfitting :: Memorises examples; poor generalisation
ROW: Catastrophic forgetting :: Loses general abilities
ROW: Safety drift :: Fine-tuning can weaken refusals; re-run safety evals
TIP: Free practice: Google Colab or Kaggle notebooks (free GPU quotas) with Hugging Face TRL / PEFT or Unsloth on a 0.5B–3B open model.
