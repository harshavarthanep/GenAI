## i-llm | layers | LLM fundamentals | Concepts asked in almost every GenAI interview
IQ: How does an LLM generate text? => It tokenises the input, embeds the tokens with positional information, passes them through stacked transformer blocks with causal self-attention, outputs a probability distribution over the vocabulary for the next token, samples one according to decoding settings and repeats autoregressively until a stop condition. => It guesses the next word piece again and again, using everything written so far.
IQ: Why do we scale attention by √d? => Dot products grow with dimension, pushing softmax into saturated regions with tiny gradients; dividing by √dₖ keeps the variance stable and training well-behaved. => It stops the scores becoming too big so learning stays smooth.
IQ: What is the KV cache? => During generation, keys and values of previous tokens are stored so each new token only computes its own projections and attends to cached ones, cutting repeated computation; it costs memory that grows with sequence length and batch size. => The model remembers its earlier calculations instead of redoing them.
IQ: What is Mixture-of-Experts? => An architecture where a router sends each token to a small subset of expert feed-forward networks, increasing total parameters and capacity while keeping per-token compute low. => Many specialists, but each question only goes to a couple of them.
IQ: What are temperature and top-p? => Temperature rescales logits before softmax, sharpening (low) or flattening (high) the distribution; top-p (nucleus) sampling restricts sampling to the smallest set of tokens whose cumulative probability exceeds p. => Temperature is the creativity dial; top-p removes very unlikely words.
IQ: What is RLHF and what is DPO? => RLHF collects human preference comparisons, trains a reward model and optimises the policy (e.g. with PPO) against it with a KL penalty. DPO optimises the policy directly on chosen versus rejected pairs with a closed-form objective, avoiding a separate reward model and RL loop. => Both teach the model which answers people prefer; DPO is the simpler recipe.
IQ: What are reasoning models? => Models trained, often with reinforcement learning on verifiable tasks, to produce extended intermediate reasoning before answering; they trade latency and tokens for accuracy on maths, coding and planning. => Models that think longer before they answer.
IQ: What is quantisation and its trade-off? => Representing weights (and sometimes activations) with fewer bits such as 8 or 4 to reduce memory and speed up inference, at the cost of some accuracy, depending on method (GPTQ, AWQ, GGUF). => Compressing the model so it fits on smaller machines, losing a little quality.
IQ: Why do LLMs struggle with counting letters or exact arithmetic? => They operate on subword tokens rather than characters and generate by pattern prediction rather than executing algorithms; tools or code execution are more reliable. => They see word chunks, not letters, so give them a calculator.
IQ: What is "lost in the middle"? => Models tend to use information at the beginning and end of long contexts more reliably than information in the middle, so ordering and limiting retrieved context matters. => Important facts buried in the middle of a long prompt are easier to miss.

## i-rag | library | RAG & vector search | Retrieval, chunking, evaluation and failure modes
IQ: Dense vs sparse retrieval? => Sparse retrieval (BM25) matches exact terms and is strong for names, codes and rare words; dense retrieval matches meaning via embeddings and handles paraphrases. Hybrid search combines both, often with reciprocal rank fusion. => Keyword search finds exact words, vector search finds similar meaning; use both.
IQ: What is a cross-encoder reranker and why not use it for all retrieval? => It scores a query and document together with full attention, giving more accurate relevance than bi-encoder embeddings, but it is too slow to run over millions of documents, so it is applied to the top candidates only. => A careful second reader, but slow, so it only checks the shortlist.
IQ: How does HNSW work? => It builds a multi-layer navigable small-world graph; search starts at sparse top layers and greedily descends to denser layers, finding approximate nearest neighbours in roughly logarithmic time with tunable recall and memory. => A map with highways and local roads to reach the nearest points fast.
IQ: How do you handle permissions in enterprise RAG? => Store access-control metadata with every chunk, filter at query time by the user's identity and groups before ranking, keep the index synced with source permissions, and audit retrieval logs. => Only search documents the person is allowed to read.
IQ: How do you evaluate a RAG system? => Separate retrieval and generation: measure recall@k, MRR or nDCG against labelled relevant passages, and measure faithfulness, answer relevance and citation accuracy with human or LLM judges on a golden set; track latency, cost and user feedback online. => Check that it found the right pages and that the answer sticks to them.
IQ: The bot answers from outdated policies. How do you fix it? => Add incremental re-indexing on document change, store effective dates and versions, filter or boost by recency, remove superseded documents, and show sources with dates. => Update the library automatically and prefer the newest version.
IQ: What is GraphRAG? => An approach that extracts entities and relationships into a knowledge graph, often with community summaries, and retrieves over the graph to answer multi-hop or global questions better than chunk similarity alone. => It maps who is connected to what, so it can answer relationship questions.
IQ: How would you handle tables and scanned PDFs? => Use layout-aware parsers or OCR, convert tables to structured text or keep them as separate table chunks with headers, store page images for vision models when needed, and verify extraction quality on samples. => Use the right reader for tables and scans, and check what came out.

## i-agents | bot | Agents, tools & MCP | Design, reliability and safety of agentic systems
IQ: Explain the ReAct pattern. => The model alternates between reasoning about what to do next and taking an action with a tool, then incorporates the observation into the next reasoning step, looping until it can answer. => Think, act, look at the result, repeat.
IQ: How do you make tool calling reliable? => Clear tool names and descriptions, strict JSON schemas, argument validation, few tools per step, examples in the system prompt, error messages returned to the model for recovery, timeouts and retries, and evaluation on tool-use scenarios. => Describe tools clearly, check their inputs, and let the model see errors so it can fix them.
IQ: How do you prevent infinite loops and runaway costs? => Step, time and token budgets, loop detection on repeated actions, explicit success criteria, checkpoints with human approval, and monitoring with alerts. => Put a meter and a stop button on the agent.
IQ: Single agent vs multi-agent? => Start with a single agent or workflow; move to multi-agent only when tasks benefit from parallel exploration or separation of concerns, accepting higher cost, latency and coordination complexity. => One good worker first; build a team only when the job really needs it.
IQ: What is MCP and why does it matter for enterprises? => An open protocol for exposing tools, resources and prompts to AI applications in a standard way, so one integration works across many clients, with clearer boundaries for permissions and auditing. => A standard plug so company tools connect to any AI app safely.

## i-ft | sliders | Fine-tuning & evaluation | Customisation, training and measurement
IQ: Walk through a LoRA fine-tuning project. => Define the target behaviour and metrics, collect and clean high-quality examples, format as chat JSONL, split train and test, pick a base model, configure LoRA (rank, alpha, target modules) or QLoRA, train for 1–3 epochs while watching validation loss, evaluate against the base model on task, format and safety metrics, then deploy the adapter and monitor. => Gather good examples, train small add-ons, and prove it beats the original.
IQ: What is catastrophic forgetting and how do you mitigate it? => Loss of previously learned general capabilities after fine-tuning on narrow data; mitigate with PEFT methods, lower learning rates, fewer epochs, mixing in general data and evaluating broad benchmarks. => Learning the new job makes it forget old skills; train gently and keep testing old skills.
IQ: What is LLM-as-judge and what are its pitfalls? => Using a strong model with a rubric to grade outputs; pitfalls include position and verbosity bias, self-preference, inconsistency and blind spots, so randomise order, use clear rubrics, calibrate against human labels and spot-check. => An AI marking another AI's homework; useful, but check it against human marks.
IQ: BLEU and ROUGE: are they good for LLM evaluation? => They measure n-gram overlap with references and correlate weakly with quality for open-ended generation; prefer task-specific checks, semantic similarity, rubric-based judges and human evaluation. => Word-matching scores miss good answers phrased differently.

## i-ml | cpu | ML & statistics | Classic questions that still appear
IQ: Explain the bias-variance trade-off. => Expected error splits into bias (error from overly simple assumptions), variance (sensitivity to training data) and noise; increasing model complexity lowers bias but raises variance, so we choose complexity and regularisation to minimise validation error. => Too simple misses the pattern; too complex memorises noise.
IQ: L1 vs L2 regularisation? => L1 adds the sum of absolute weights, driving some to exactly zero for sparse feature selection; L2 adds the sum of squared weights, shrinking weights smoothly and handling correlated features better. => L1 deletes useless features; L2 keeps all features small.
IQ: How do you handle imbalanced data? => Use appropriate metrics (PR-AUC, recall, F1), stratified splits, class weights, resampling such as SMOTE or undersampling, threshold tuning and, where possible, more minority data. => Don't trust accuracy; give the rare class more importance.
IQ: What is a p-value? => The probability of observing results at least as extreme as the data if the null hypothesis were true; a small p-value is evidence against the null, not the probability the null is true. => How surprising the result would be if nothing were really going on.
IQ: Explain an A/B test for a new chatbot prompt. => Randomly split traffic, define a primary metric (resolution rate) and guardrail metrics (latency, complaints), compute required sample size, run for a fixed period, test significance and check segments before rolling out. => Show half the users the new version and measure which does better, fairly.

## i-python | code | Python & coding | Language and problem-solving questions
IQ: What happens when you use a mutable default argument? => The default is evaluated once at function definition, so the same object is shared across calls and mutations persist; use None and create the object inside. => The same list keeps growing every time you call the function.
IQ: How does a Python dict work internally? => It is a hash table: keys are hashed to find slots, collisions are resolved by probing, and the table resizes as it fills, giving average O(1) operations while preserving insertion order. => It turns each key into a number that points straight to its box.
IQ: Reverse a linked list. => Iterate with three pointers (prev, curr, next), redirecting each node's next to prev, in O(n) time and O(1) space. => Walk along the chain and flip each arrow backwards.
IQ: Find the top K frequent words. => Count with a hash map (Counter), then use a heap of size K or sort by frequency; heap gives O(n log k). => Count every word, then keep the K biggest counts.
IQ: Explain async vs threads vs processes. => Async uses a single-threaded event loop for many concurrent I/O tasks; threads share memory and suit blocking I/O but are limited by the GIL for CPU work; processes have separate memory and give true parallelism for CPU-bound work. => Async juggles waiting tasks, threads share a kitchen, processes are separate kitchens.

## i-design | compass | System design prompts | Practise these out loud in 30–45 minutes
IQ: Design a customer support assistant for an e-commerce company. => Clarify channels, languages, volume and handoff policy. Classify intent, route FAQ queries to RAG over help-centre content, call tools for order status and refunds with authentication, keep conversation state, escalate to humans with context, apply guardrails and PII masking, cache common answers, route by complexity between small and large models, and measure resolution rate, CSAT, latency and cost. => Answer common questions from the help pages, check orders with tools, and hand tough cases to people.
IQ: Design an AI coding assistant for a 2,000-engineer company. => Index repositories with code-aware chunking and symbol graphs, retrieve relevant files for the current context, enforce repository permissions, keep secrets out of prompts, provide inline completion with a fast model and chat or agent mode with a stronger model, run tests in sandboxes, log acceptance rates and measure productivity and defect impact. => Let it read the right code safely, suggest changes fast, and test before trusting.
IQ: Design a meeting summarisation service. => Ingest audio, run speech-to-text with speaker diarisation, chunk long transcripts, summarise hierarchically, extract decisions and action items as structured output with owners and dates, allow user edits, respect consent and retention policies, and evaluate with human-rated rubrics. => Turn recordings into text, then into a short summary and to-do list, with permission.
IQ: Design an internal "ask the company" search across Drive, Slack and wikis. => Connectors with incremental sync, permission mirroring, unified chunk schema with metadata, hybrid index and reranker, answer synthesis with citations, freshness signals, query analytics and feedback loops, plus quotas and cost controls. => One search box that reads all company tools, but only shows what you may see.

## i-behave | user | Behavioural | Show ownership, impact and learning
IQ: Tell me about a time you used AI to solve a real problem. => Use STAR: describe the business pain, your responsibility, the AI solution and alternatives you considered, how you evaluated it, and the measurable result such as hours saved, accuracy or adoption, plus what you would improve. => Problem, what you built, how you tested it, what changed.
IQ: Tell me about a failure. => Choose a real, moderate failure, own your part, explain what you learned and the process change you made, and show the improved result later. => Be honest, show the lesson, prove you improved.
IQ: How do you keep up with AI changes? => Follow primary sources such as official model release notes, papers and documentation, test new tools hands-on in small experiments, keep an evaluation set to compare models objectively, and share learnings with the team. => Read the official updates, try things yourself, and measure before switching.
